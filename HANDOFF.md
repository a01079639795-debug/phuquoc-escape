## 1. Что это

Демо-MVP travel-маркетплейса для острова Фукуок: каталог жилья и байков,
заявки, кабинет, админка. Аудитория русскоязычная, данные учебные.

**Стек:** Next.js 16 (App Router, Turbopack) · TypeScript · Prisma 6 ·
PostgreSQL 18 · Tailwind v4 · zod.

**Архитектура:** модульный монолит. Бизнес-логика в `src/server`, не зависит
ни от Next, ни от HTTP — при переносе API в отдельный сервис слой уезжает
целиком.

## 3. Что НЕ сделано

- личный кабинет и админка (интерфейсы);
- форма заявки на странице объекта — **сервер готов и покрыт тестами**,
  интерфейса нет;
- страницы каталога `/hotels` и `/bikes` со списком и фильтрами;
- электронная почта (по прямому указанию — только Telegram);
- `Booking`, `Payment`, CRM — этапы 2–4, трогать нельзя.

## 4. Как запустить

База (Docker не нужен, поднимается из npm-пакета):

```bash
npm run dev:db
```

Оставить окно открытым. Данные лежат в `.devdb`, повторный сев не делается.

Сайт в другом окне:

```bash
npm run dev
```

Открыть `http://localhost:3000`. Демо-аккаунты: `admin@phuquoc.demo`,
`manager@phuquoc.demo`, `ivan@example.com` — пароль у всех `demo1234`.

Проверки:

```bash
npm run typecheck && npm run build
```

```bash
npm test
```

## 5. Решения, которые уже приняты — не пересматривать

Их обсудили и утвердили; возврат к ним будет потерей времени.

| Решение | Почему |
|---|---|
| `Listing` — общая сущность для жилья, байков и будущих услуг | иначе каждый новый тип требует своей системы |
| `ListingUnit` — единица инвентаря | на этапе 2 именно она бронируется |
| `Request` ≠ `Booking` | заявка это лид, бронь блокирует инвентарь |
| Деньги — целые в **минорных** единицах (VND — донги, USD — центы) | float в деньгах даёт расхождения |
| `timestamptz` для отметок времени, `date` для дат аренды | иначе прямой SQL и BI читают время неверно |
| Единый canonical slug на все языки | отдельные слаги добавятся полем в `ListingTranslation` |
| Смена обложки — **только** под `SELECT … FOR UPDATE` по `Listing` | без блокировки остаются две обложки, воспроизведено тестом |
| Контент только на RU; вьетнамские — названия районов | добавление языка = вставка строк в `*Translation` |
| Интерфейс русский, а не английский | данные объектов русские, смешивать хуже |
| Вместо выдуманных рейтингов — категория звёздами | отзывов не собираем, «4.8» было бы неправдой |

## 6. Визуальное направление

Задано референсом пользователя (скриншот маркетплейса). Реализовано:

- кремовый лист `#FBF6EE`, бирюза `#0F4C5C`, золото `#F0B429` на действиях;
- Manrope в имени острова на первом экране, Playfair Display в заголовках
  разделов, Marck Script в рукописных вставках, Golos Text в тексте;
- герой с ожившей фотографией, двухцветным «Phú Quốc» и панелью поиска внизу;
- три фото-плитки, каталог по 4 карточки с рабочей каруселью,
  светлый аквамариновый блок острова с картой мест и районов, полоса гарантий.

### Ожившая фотография первого экрана

Первый экран — не анимация поверх снимка, а сам снимок, в котором работает
то, что должно работать. Ничего не дорисовано: и кабинки, и вода — пиксели
исходного кадра.

`scripts/hero-scene.mjs` разбирает `public/images/hero/beach.jpg` на слои:

- прослеживает по пикселям линию троса (провис описан многочленом,
  невязка 0,65 px) и измеряет обе кабинки;
- вырезает ближнюю кабинку с настоящей альфой — свет и цвет совпадают
  с кадром, потому что это тот же кадр;
- стирает обе кабинки со снимка и возвращает на их место трос, рисуя
  его собственный поперечный профиль, снятый с чистых участков;
- строит маску воды по признаку «синего больше, чем красного» ниже горизонта;
- складывает геометрию в `src/components/hero/scene.generated.ts`.

Дальше `LivePhoto.tsx` ведёт четыре кабинки по этой линии: размер падает по
закону, снятому с двух кабинок на снимке, скорость постоянна **на тросе**, а
не на экране (вдали ползут, вблизи идут заметно быстрее), у дальней опоры и в
засветке они растворяются. Вода — шейдер в `water.ts`: те же пиксели, смещение
до 2,6 px по перспективе плоскости воды, у горизонта почти ноль.

Прогонять скрипт заново нужно только при замене снимка. Не прогнали — не
страшно: `src/lib/hero-scene.server.ts` сверяет отпечаток исходника и при
несовпадении отдаёт обычную неподвижную фотографию.

**Блок острова — одна карта, два набора точек.**

Карта — вид Фукуока с высоты (`public/images/island/phu-quoc-3d.webp`).
Нарисованный SVG-силуэт с 3D-плитой, который стоял здесь раньше, снят по
прямому указанию: остров показывает снимок, а не схема.

Переключатель меняет не карту, а то, что на ней отмечено:

- **Что посмотреть** (по умолчанию) — восемь мест: ВинВандерс, Бай Дай,
  Гранд Ворлд, канатка на Хон Тхом, Дуонг Донг, Бай Сао, пагода Хо Куок,
  Сансет-таун. Список редакционный, ведётся в
  `src/components/explore/attractions.ts`; появится админка — сущность
  заводится в схеме, а файл становится сидом.
- **Районы** — семь районов из базы, с описаниями и координатами оттуда же,
  пронумерованы с севера на юг.

Маркер — номер на карте, название всплывает у выбранного и под курсором:
пятнадцать подписей разом закрыли бы половину острова. На телефоне подписи
не показываются вовсе, выбор идёт из списка под картой.

Координаты маркеров — доли кадра, а не широта с долготой: снимок сделан с
высоты и под углом, географическая сетка на него не ложится. Точки
расставлены по узнаваемым местам самого кадра.

Сам снимок пришёл с впечатанными латинскими подписями, которые нельзя ни
перевести, ни нажать. `scripts/island-map.mjs` их стирает: на месте подписи
ищется похожий кусок той же картинки (сравнение по рамке вокруг пятна) и
переносится с мягким краем. Исходник лежит в `assets/island-source.png`.

## 7. Шероховатости, о которых надо знать

| Что | Детали |
|---|---|
| `npm run test:all` подвисает | встроенный Postgres на Windows не всегда гасится; сами тесты зелёные. Запускать наборы по одному и не одновременно с `npm run dev:db` |
| Накопление процессов `postgres.exe` | после прерванных прогонов остаются; снимать перед новым запуском |
| Кэш `tsconfig.tsbuildinfo` | после правки `lib`/`paths` в tsconfig удалить, иначе tsc показывает старые ошибки |
| Скриншоты в этой среде | панель браузера не отображалась; проверка шла через дерево доступности, вычисленные стили и сборку кадра на canvas, не глазами |
| `requestAnimationFrame` в этой среде | пока панель скрыта, кадры не идут: кабинки и вода расставляются первым синхронным вызовом, но само движение здесь не проверить — только в обычном браузере |
| Изображения в bash-скриптах | правки файлов через `node -e` с шаблонными строками ломались об экранирование; надёжнее Write/Edit |
